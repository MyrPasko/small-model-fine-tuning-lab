# Small Model Fine-Tuning Test Operations

## Ownership

Aira owns all testing for `small-model-fine-tuning-lab`, including:

- defining behavioral test contracts and acceptance evidence;
- writing and maintaining unit, data-contract, integration, evaluation, and regression tests;
- creating synthetic fixtures, mocks, and deterministic test helpers;
- configuring test discovery and test-only tooling;
- running tests and diagnosing failures;
- reporting exact commands, counts, results, and checks not run.

Myroslav implements production code by default. Do not assign test-writing tasks to him. Test ownership does not authorize Aira to change production code unless Myroslav explicitly delegates that bounded implementation step.

## Working Contract

1. Derive tests from the accepted behavioral contract, not from incidental implementation details.
2. Inspect existing production code and tests before editing. Preserve unrelated changes.
3. Prefer deterministic, offline tests. Use synthetic fixtures and mocks; never call real external tools or APIs from tests.
4. Keep BFCL evaluation data isolated from training and ordinary test fixtures. Do not copy benchmark rows into unit tests unless an approved evaluation adapter explicitly requires them.
5. Run tests under the project's supported environment. Record the exact command, interpreter, discovered test count, pass/fail result, and relevant skipped checks.
6. When a test exposes a production defect, explain the violated contract and return the production fix to Myroslav unless he requests takeover. Do not weaken assertions merely to obtain a green result.
7. When a test itself is incorrect or brittle, Aira repairs the test and explains the correction.
8. Use `$project-git-ops` for staging, commits, pushes, pull requests, merges, and main synchronization.

## Current Foundation

- Supported local interpreter: uv-managed Python 3.12 in `.venv`.
- Current test framework: standard-library `unittest` until a later tooling decision is approved.
- Project-wide discovery command: `PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v`.
- Python environments and generated bytecode must remain outside the Git source contract.

## Guardrails

- Do not install test dependencies, download datasets/models, or run backend/training workloads without the relevant explicit approval.
- Do not fabricate test evidence or infer a pass from zero discovered tests.
- Do not commit secrets, real credentials, private payloads, model weights, datasets, caches, or generated checkpoints as fixtures.
- Keep implementation review distinct from test correctness: green tests are necessary evidence, not proof that every requirement is satisfied.

## Handoff

Report tests added or changed, production behavior covered, exact execution evidence, failures or gaps, and the next production-code action when one exists. Myroslav should receive production assignments, not test implementation work.
